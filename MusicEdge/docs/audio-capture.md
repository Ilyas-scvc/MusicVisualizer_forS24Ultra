# Откуда брать звук для визуализации (подготовка к этапу 2)

Документ отвечает на один вопрос: что именно реально работает на Galaxy S24 Ultra
с Android 14+, если приложение хочет реагировать на музыку, которую играет **другое**
приложение. Ниже разделены гарантированные факты из документации Android и то, что
обязательно нужно измерить на устройстве.

## Вариант 1. `android.media.audiofx.Visualizer(0)`

Что документировано:

- `Visualizer` — это `AudioEffect`, который подключается к аудиосессии;
- сессия `0` означает «глобальный выходной микс»;
- для сессии `0` документация Android явно требует разрешение `RECORD_AUDIO`,
  плюс `MODIFY_AUDIO_SETTINGS` для работы с аудиоэффектами;
- API отдаёт `getWaveForm()` (8-битный PCM) и `getFft()` (комплексный спектр),
  размер задаётся `setCaptureSize()`, а частота — `setDataCaptureListener(..., rate, waveform, fft)`,
  где `rate` в миллигерцах и ограничен `Visualizer.getMaxCaptureRate()`.

Что нужно проверить на реальном устройстве (это **не** гарантировано):

- начиная с Android 9/10 платформа последовательно закрывает сторонним приложениям
  доступ к чужому аудиопотоку; на многих современных устройствах `Visualizer(0)`
  создаётся успешно, но возвращает тишину (нули) для звука других приложений;
- поведение зависит от OEM-прошивки, поэтому по One UI на S24 Ultra нельзя делать
  вывод из документации — нужен замер.

**План проверки (входит в этап 2).** При первом включении звукового эффекта
запускается короткая диагностика: создаём `Visualizer` на сессии 0, читаем ~1 секунду
кадров во время заведомо играющей музыки и считаем дисперсию сигнала. Нули или
плоская линия = источник не работает. Результат показывается в UI («Audio source:
Visualizer / нет данных»), а не прячется за молчаливой деградацией анимации.

Ограничение по приватности: `RECORD_AUDIO` — «опасное» разрешение с индикатором
микрофона. Просить его до того, как измерение подтвердит пользу, нельзя, поэтому в
MVP оно не объявлено вовсе.

## Вариант 2. `AudioPlaybackCapture` + `MediaProjection` (Android 10+)

Документированное поведение:

- захват чужого воспроизведения возможен только если приложение-источник разрешило
  его политикой `AudioAttributes.ALLOW_CAPTURE_BY_ALL`;
- захватываются только потоки с usage `MEDIA`, `GAME`, `UNKNOWN`;
- нужен `MediaProjection`, то есть системный диалог согласия;
- на Android 14 захват требует foreground-сервиса с типом `mediaProjection`, и
  разрешение выдаётся на один сеанс — токен нельзя переиспользовать.

Практическое следствие: многие музыкальные сервисы (в том числе крупные стриминги)
запрещают сторонний захват, поэтому вариант работает не для всех приложений. Плюс
он противоречит принципу «настроил и забыл»: диалог согласия придётся проходить
заново после каждой перезагрузки/перезапуска сеанса.

Вывод: это допустимый **fallback по выбору пользователя**, но не поведение по
умолчанию.

## Вариант 3. Микрофон

Технически работает всегда, но: постоянный индикатор микрофона, запись окружающего
шума вместо чистого сигнала, заметный расход батареи и очевидные вопросы к
приватности. Для этого приложения отклонён.

## Вариант 4. Без анализа звука

Если ни один источник не отдаёт данные, визуализатор всё ещё может работать
осмысленно, опираясь на то, что медиасессия даёт легально:

- факт воспроизведения (`PlaybackState`);
- позицию и скорость воспроизведения;
- метаданные и обложку (этап 5 — палитра из обложки).

На этих данных корректно работают `Breathing`, `Rainbow`, `Gradient`, `Wave` и
`Static` — они анимируются по времени, а не по амплитуде. Не работают только
`Bass Pulse` и `Spectrum`, и в UI такие эффекты должны честно помечаться как
недоступные, а не «работать» на выдуманных данных.

## Итоговый порядок для этапа 2

1. `AndroidVisualizerSource` (сессия 0) — пробуем первым, с диагностикой;
2. если данных нет — предлагаем пользователю включить `PlaybackCaptureSource`
   (осознанный выбор + системный диалог);
3. если и он недоступен для конкретного приложения — переключаемся на эффекты,
   которым звук не нужен, и честно показываем это в интерфейсе.

Интерфейс `AudioSource` в пакете `audio/` уже описывает ровно этот контракт:
`start(updatesPerSecond)` возвращает `false`, если источник недоступен, а
`isActive` показывает, идут ли реальные данные.
